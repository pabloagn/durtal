# Task 0268: Sourced Links Between Works (SLN-363)

**Status**: In Progress

## Overview
A work can now be linked to another by hand: a film adapted from a book (or a
book from a film), a remake of a film, a flanker of a perfume, or any work
inspired by another, with a source. Links are directed, read from both ends,
and never inferred from a shared title, genre or taste. Every detail page lists
them in its own section, apart from the related rows that only suggest.

## Implementation Details

**Data** (`src/lib/db/schema/work-relations.ts`, docs 02 "Links between works"):
- `work_relations`: type, from work and kind, to work and kind, source, notes.
  Each end is a composite key to `works (id, kind)`, so the allowed kind pairs
  are a plain check (`work_relation_pair_check`): adaptation film to book or
  book to film, remake film to film, flanker perfume to perfume, inspiration
  any pair. Also: no self link, an inspiration needs a source, one link per
  pair of works and type whichever way it points
  (`work_relation_pair_unique` on least/greatest).
- Migration `0057_work_kind_keys` adds `UNIQUE (id, kind)` on `works`;
  `0058_work_relations` adds the table. Two files because the unique key must
  exist before the keys that point at it; both generated by drizzle-kit on top
  of `0056_publisher_backgrounds`.
- The source is a plain key to `source_records`; the services check that it
  belongs to the first work. A cited source cannot be deleted
  (`deleteCitedSource` says so); removing a link keeps its source.

**Rules** (`src/lib/catalogue/work-relations.ts`): the types, their kind
pairs, the labels from each end ("Adapted from" and "Adapted as"), which kinds
the other end may be from either side, and that only an inspiration needs a
source.

**Services** (`src/lib/actions/work-relations.ts`): `getWorkRelations` (both
directions, the other work's collection, creators and address, the source),
`createWorkRelation` (plain messages for a self link, a kind pair, a missing or
foreign source and a duplicate; a new source is cited for the first work and
removed again if the link is refused), `deleteWorkRelation`,
`searchWorksForRelation` (title search in the open collections a link fits),
`getWorkSourceChoices`.

**Merges**: a book merge moves the merged book's links to the kept book, drops
a link between the two (it would point at itself) and a link the kept book
already has (`src/lib/harmonization/work-relation-merge.ts`). `referencesTo` and
the merge guard accept a key on `works (id, kind)` as a reference to the id;
any other composite key still blocks a merge.

**Screens** (`src/components/catalogue/work-relations.tsx`, docs 04 "Linked
works"): `LinkedWorksSection` on the film page (after Crew), the perfume page
(before the gallery) and the painting page (before Sources), with "Link a
work"; the book page shows it after Editions only when a link exists, and its
actions menu has "Link a Work". `WorkRelationDialog` offers the links this
work can take both ways, a title search in the kinds that fit, a recorded
source of the first work or a new one, and notes. Sources cited by a link
starting on the page show "Cited here".

**Explainable suggestions**: the existing related rows already say why each
work is shown (film: director, shared cast and genres by name; perfume: house,
perfumer, shared notes; book: author, series, collections, marks). They stay
as they were, below and apart from the recorded links.
